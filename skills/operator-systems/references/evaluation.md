# Paired creative evaluation

Freeze the baseline before changing prompts. Save hashes of source skills and brand material, provider settings, product/reference images, selected personas, briefs, exact requests, generated artifacts, usage and failure records. A saved baseline can be compared later without rerunning it under changed guidance.

For 25 before and 25 after static ads, use 25 paired briefs. Match product, persona, age/role, angle, awareness, static archetype, aspect ratio, reference, image provider, resolution and requested counts. Vary those axes across pairs to exercise the portfolio; hold them within each pair. If provider seeds are supported, record the setting, without promising identical or deterministic output. Treat the prompt/skill/context change as the intervention.

Compare the avatar-to-storyboard journeys on the same brief and identity specification. Verify reference selection, required character-sheet views, cast continuity, complete dialogue/visible text, shot order, product action, frame assets and timing. Preserve every planned scene; more panels are appropriate when one storyboard cannot convey the full ad.

Perform structural checks before judging: expected counts, complete fields, accessible image files, nonempty decoded pixels, exact text preserved in prompts, known IDs, full script coverage, valid continuity, and no success status on missing outputs. Use the app's applicable checks and preserve the chosen claim-check setting.

Shuffle labels independently of before/after and hide the condition from judges. A visual judge must receive the pixels, source product/character references and the original brief. Use concise anchored dimensions: brief/argument fit, buyer relevance, brand/voice fidelity, copy clarity, rendered text legibility, product fidelity, character consistency and production readiness. Mark unavailable evidence as unassessed. Record independent verdicts and disagreements; do not average away a missing asset or identity failure.

Report each pair and portfolio: input/output/cache tokens, spend, latency, retry/failed-call cost, completion rate, substantive issue counts, blind score/win/tie/loss, and static diversity across the allowed archetypes, messages, personas and visual levers. Static-only requests are not penalized for absent video. Distinguish estimates from actual usage. Report cost per accepted asset, not just cost per successful API call.

Accept an efficiency change when required facts survive, structural checks pass, and blind evaluation shows no material quality loss across representative cases. If a smaller packet harms one stage, restore that stage's needed evidence instead of raising every stage's budget. A 25-pair creative comparison describes these outputs; it does not establish future CTR, conversion lift, or Meta retrieval Entity IDs. Only live performance data can establish those outcomes.

# Operator systems

Give each stage the facts and instructions its output depends on. Preserve the app's chosen context level, model route, brand, product, avatar, and checks. A smaller packet is useful only when it preserves these dependencies and the result remains valid.

For packet composition, read [stage-packets.md](references/stage-packets.md). For before/after comparison, read [evaluation.md](references/evaluation.md). Framework libraries and source examples are reference material; do not add them all to every request.

## Context contract

Resolve references before calling a model. Distinguish verified brand facts, attributed customer language, research hypotheses, and creative choices. Preserve an entire claim's scope: product, amount, serving, timeframe, study population, and qualification. A source identifier alone is not evidence for a model that cannot retrieve it.

The required set depends on the stage. Preserve relevant product identity, selected offer terms, buyer objection, brand voice examples, exact locked copy, visual identity anchors, reference role, and applicable prohibitions. Keep mandatory facts before examples when context is constrained. If required material does not fit, use a larger budget or split the task; never cut a required sentence midway.

Place reusable rules and stable product facts before dynamic material so providers can cache them. Deduplicate repeated points, keeping their richest supported formulation. Select optional whole records by relevance and source strength. Keep contradiction and confidence notes when they affect the decision.

A designer sees visual DNA; a copywriter sees voice and buyer language. Both see the facts visible in their deliverable. A judge sees the actual output and the original brief. Give a patcher only the failed field, the issue, and its dependencies. Do not make a model recompute deterministic counts, budgets, coverage, or arithmetic.

## Output and execution

Return the requested artifact and the minimal structured metadata needed by the next stage. Omit restated inputs, process narration, unused variants, and duplicate rationales. Never trade away complete copy, shot coverage, claim qualifications, or identity constraints to hit an output-token target.

Persist each stage's input hash, skill versions, provider settings, exact request, raw response, validated result, usage, cost, and retry lineage. Resume from the last valid artifact. A failed or partial generation remains failed or partial; never substitute stock or synthetic output and mark it successful.

Use bounded retries tied to a named failure. Reinspect rendered images after edits. For concurrent paid jobs, account for in-flight reservations as well as settled cost; every retry consumes the same run's budget. Source starter code is an illustration, not an instruction to replace the app's database or add Slack, Redis, Render, or campaign execution.

# Review the actual proposal

Changed D2C adaptation of the archived design references. Keep two assessments distinct; neither substitutes for the other.

## Visual review

Inspect mobile first, then desktop. Can a buyer identify the actual product, connect it to the traffic promise, understand the main benefit and find the next action? Does each section add information? Is evidence authentic and relevant? Does the focal move fit this brand? Check actual copy length, hierarchy, grouping, crops, rhythm and transformation rather than a template score. A repeated product grid can be correct for a collection. An unexplained succession of the same card pattern is a concern, not an automatic ban.

Describe the visible observation, buyer consequence, owning section, viewport, confidence and localized repair. Preserve strong parts. Do not prescribe invented promises, new discounts or unapproved strategy to improve appearance. A screenshot cannot establish purchase behavior, revenue or actual loaded font identity.

## Technical review

Use computed browser evidence for overflow, font failures, unreadably small text, simple solid-background contrast, clipped text, unnamed controls and potentially undersized standalone targets. Hidden controls do not count. Treat target-size signals as review warnings because spacing and inline exceptions matter. Compositing unsupported gradients, image backgrounds, translucent layers or opacity effects needs visual inspection; do not call unknown contrast a pass. Limited local checks are not WCAG certification.

Inspect keyboard order and focus, 200% zoom, reduced motion and essential purchase terms separately when behavior is present. Local exports can establish destination wiring and rendering; actual cart and payment behavior requires merchant integration testing. Report the boundary.

## Repair and handoff

Use the saved approval and shared design system. Fix one owning section or a justified shared rule, retain the rest, rerender and compare. Show a next action for each material issue. No automatic paid repair. Export is a reviewable proposal; design approval is not proof of conversion uplift or a store deployment.
